# 山风 Blog 文字规范（提案 v1）

> 依据：设计稿 `design/shanfeng-ui/baseline/tokens.css`，加上现有代码的实际用量盘点。
> 目标：字号从「70 种」收到 **9 档**，行高、字重、字距各一套；改的时候只改 `src/styles/type-scale.css`。

## 一、现状盘点（2026-11）

扫了 `src` 下全部 `.css/.astro/.svelte`：

| 项 | 不同取值 | 说明 |
| --- | --- | --- |
| `font-size` | **70 种**（185 处声明） | 混着 `var(--fs-*)`、`0.75rem`、`14px`、`0.9rem`、`max(0.75rem, 0.875rem)` 等写法 |
| `line-height` | **27 种** | 同一个角色出现过 `1.5 / 1.6 / 1.75 / 1.75rem` 四种 |
| `letter-spacing` | **11 种** | `0.01 / 0.02 / 0.04 / 0.08 / 0.12 / 0.14 / 0.16 / 0.18 / 0.2em`，还有 `-0.04em` |
| `font-weight` | **7 种** | 含 `800`、`bold`、`inherit` |

具体病灶：

1. **小字挤在一起**：`0.75rem(10.8px) / 0.8125rem(11.7px) / 0.85rem(12.2px) / 0.875rem(12.6px) / 13px / 14px` 六种「小字」，肉眼分不出，代码里到处挑一个用。
2. **rem + 响应式根字号**：桌面根字号是 `clamp(14.4px … 17px)`，所以 `0.8125rem` 在用户缩放后是 11.7 / 12.4 / 13.8 之间的某个数，落在半像素上，行高也跟着抖。
3. **中英混排没有统一处理**：数字（字数、时长、日期）没有 `tabular-nums`，列表里数字跳动。
4. **字距失控**：副书名用了 `0.08em`（≈14 字距单位），标签用 `0.2em`，标题用 `-0.04em`——同一屏三种意图。

## 二、字号阶梯（9 档，单位 px）

**改成 px 写死**（不再用 rem）：桌面/手机各一套，不跟根字号缩放，永远落在整数像素上。

| 令牌 | 桌面 | 手机 | 用途 |
| --- | --- | --- | --- |
| `--fs-display` | 64 | 34 | 首页壁纸大标题、书页 banner 书名 |
| `--fs-h1` | 44 | 26 | 文章页 banner 标题 |
| `--fs-h2` | 29 | 22 | 页面主标题、文章标题、合集页标题 |
| `--fs-h3` | 22 | 19 | 区块标题（序言、第一篇、关于这本书） |
| `--fs-item` | 18 | 17 | 卡片标题、目录条目、小节标题 |
| `--fs-body` | 16 | 15 | 正文、简介、篇首语、卡片摘要 |
| `--fs-meta` | 13 | 13 | 元信息、标签、按钮、导航、副书名（ui/label/sub 都指向它） |

**页面预算：任意一屏最多 5 档。**
banner 页 = `64 · 22 · 18 · 16 · 13`；内容页 = `29 · 22 · 16 · 13`（有卡片时加 18）。
实测：首页 4 档、合集页 4 档、文章页 5 档、书页 5 档。

相邻比值：1.08 / 1.32 / 1.22 / 1.22 / 1.13 / 1.1 / 1.12 / 1.08。小字区（12–18）步长细、大标题区跳得开，符合「正文密、层级拉开」的阅读节奏。

> 设计稿原本是 64/29/22/18/16/14.5/13.5/13/12 十档，其中 `14.5 / 13.5` 只差 1px、`13 / 12` 只差 1px，实际渲染分不出来。合并成上面 9 档，大标题多插一档 44 给书页书名用（设计稿里 banner 书名是手调的 92px，属于一次性特例）。

## 三、行高（5 档）

| 令牌 | 值 | 用于 |
| --- | --- | --- |
| `--lh-tight` | 1.1 | display / h1 / h2（大字，行高收） |
| `--lh-snug` | 1.35 | h3 / item（卡片标题，两行也好看） |
| `--lh-ui` | 1.5 | meta / label / 按钮 / 导航 |
| `--lh-quote` | 1.6 | 引用块（比正文松一档，形成停顿） |
| `--lh-body` | 1.75 | 正文、简介、篇首语 |
| `--lh-loose` | 1.9 | 文章页长文 |

规则：行高只写无单位数字，**不再出现 `1.75rem` 这种写法**（它随字号变化，两行就叠在一起）。

## 四、字重（4 档）

| 值 | 角色 |
| --- | --- |
| 400 | 正文、摘要、元信息 |
| 500 | 导航、按钮、标签、侧栏组件标题 |
| 600 | 所有标题（h1–h3、卡片标题、小节标题） |
| 700 | 仅 display 大标题、书页 banner 书名 |

`800` / `bold` / `inherit` 全部收掉：中文黑体在 800 上会糊成一团，700 已经是上限。

## 五、字距（4 档）

| 令牌 | 值 | 用于 |
| --- | --- | --- |
| `--ls-tight` | -0.02em | ≥ 40px 的标题（display / h1） |
| `--ls-snug` | -0.01em | 22–32px 的标题（h2 / h3） |
| 默认 | 0 | 正文、卡片标题、列表 |
| `--ls-wide` | 0.04em | 12–13px 的小标签、序号、全大写英文 |

`0.08em / 0.12em / 0.14em / 0.16em / 0.18em / 0.2em` 六种全部废弃。中文小字加字距会散架，只给「英文/数字标签」用 0.04em。

## 六、排版细则

1. **数字等宽**：字数、时长、日期、章节号统一 `font-variant-numeric: tabular-nums`，列表里不跳。
2. **中英混排**：中文与英文/数字之间加空格（`3829 字`、`21 章`、`iPhone 16`）；标点用全角。
3. **行宽**：正文容器 `max-width: 38em`（约 34–38 个汉字）；短文本（简介、篇首语）可以放宽到 `52em`，但**不要无限宽**——超过 55 字读起来会回行丢失位置。
4. **中文不用斜体**，需要强调用字重 600 或主色，不用 `italic`。
5. **最小字号 12px**，不再出现 10.8 / 11.7 / 12.2 / 12.6 这类半像素值。
6. **标题不孤字**：`text-wrap: balance`，配合容器宽度调整。

## 八、落地方式

1. 重写 `src/styles/type-scale.css`：9 个字号 + 5 个行高 + 2 个字距令牌，px 单位，手机档放 `@media (max-width: 767px)`。
2. 全站替换：`var(--fs-*)` 保留，把散落的 `0.75rem / 14px / 0.85rem` 等归到令牌；`font-weight: 800 → 700`。
3. 逐页验收顺序：导航 → 首页卡片 → 文章页 → 合集页 → 书页 → 侧栏。
4. 每页改完用 `check_design` 量（它会报「字号太杂」，目标是单屏 ≤ 5 档）。
