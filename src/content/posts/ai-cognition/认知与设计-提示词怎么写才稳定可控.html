提示词怎么写才稳定可控

从「列了一堆要求却跑偏」到「按任务把要素配齐」：构成要素、推理框架、可直接抄的模板库，今天一次讲透。

先带走三句话

  1. 稳定可控的底层公式：信息完备（按任务配齐：角色、任务、约束是底线，示例、步骤、受众看复杂度加）＋ 过程外显（思维链让推理可见）＋ 噪声压制（多次采样 / 评分），三者叠加，输出才从「看运气」变「可预期」。
  2. 推理框架深度对齐任务复杂度：线性任务用思维链，多解需取舍用思维树（打分即反思雏形），够用即停，不堆最深的。
  3. Prompt 不是孤岛：事实用检索补、底线用规则校验，Prompt 只管「怎么想」。

01提示词工程的四层拆解

按「稳定可控」拆成四个层面

图 1 · 提示词工程的四层结构（推理激发层内含 CoT → 自洽 → 思维树 → 反思 递进）
推理激发层本身是一条递进链，不是越深越好，而是匹配任务复杂度（详见 02 案例②与 03 判据二）。
推理激发的递进链：思维链（让模型一步步想，减少跳步出错）→ 自洽（同一题采样多次、投票表决，用「多数」压住单次随机性）→ 思维树（不止线性链，允许多分支探索 + 评估取舍）→ 反思（生成后自我批评修正，形成闭环）。

从「原版 vs 优化版」对比能直接抽出的结论：稳定可控不是四个独立动作，是同一件事的四个面：让模型没有自由发挥的空间。而且这层是所有落地方式的地基：RAG / Agent / 微调都叠在提示词之上，提示词写不稳，叠什么都在抖。

02两个调优对比案例

案例① 账户数据图表提示词：原版 vs 优化版

同一件事、写法不同，结果能差多少，这组对比直接说明。原版把数据库连接、代码规范等「怎么做」的约束堆在最前，但「交付什么样的工程、给谁用、验收标准」反而没说（敏感的主机 / 账号信息已脱敏）。优化版补了角色，并把关键约束前置、分层组织。

原版（节选）：五段要求平铺，无角色、无目标

请在当前项目目录下，生成一套完整的账户数据可视化工程代码，具体要求如下： ### 一、项目基础配置 1. 项目目录结构：按模块化设计，包含以下目录/文件（需自动创建）： - config/：存放数据库配置文件 - database/：存放数据库连接与操作代码 - utils/：存放工具函数；visualization/：存放可视化代码；main.py：工程入口 …… ### 二、数据库连接要求 1. 数据库类型：MySQL 2. 账户信息（需写入配置文件）：主机 / 端口 / 用户名 / 密码 / 数据库名 / 时区（已脱敏，此处略） …… ### 三、数据统计与可视化要求 ……（每日 / 每月 / 整体趋势图的维度与图表类型、Top50 排名规则，约 20 行，略） ### 四、代码规范要求 1. 编程语言：Python 3.11.9 2. 代码风格：遵循PEP8规范，包含详细注释（函数说明、关键逻辑注释） 3. 异常处理：捕获数据库连接异常、数据查询异常、可视化生成异常，给出友好提示 …… ### 五、额外要求 1. 在工程根目录生成README.md，说明项目结构、环境配置步骤、运行方法 ……

优化版（节选）：角色 → 目标 → 约束前置，再分层展开

# 角色 你是一位精通Python数据工程与可视化的资深开发人员。 # 目标 请在当前目录下构建一个模块化的账户数据可视化工程。该工程需要从MySQL读取广告投放数据，进行清洗聚合，并生成交互式趋势图与排名报表。 # 约束&环境 1. 编程语言：Python 3.11+ 2. 核心库：SQLAlchemy（数据库交互）、Pandas（数据处理）、Plotly（可视化）、python-dotenv（环境变量） 3. 运行模式（关键）：代码需支持Mock模式。当检测到无法连接数据库或配置了USE_MOCK=True时，自动生成符合表结构的随机模拟数据，确保工程在无数据库环境下也能完整运行并生成图表。 ……（中间略：项目目录 / 数据库模式 / 功能需求 / 命令行参数，约 60 行） # 代码质量 - 代码需遵循 PEP8 规范。 - 关键逻辑（特别是Mock生成和ORM查询）必须包含中文注释。 - 异常处理：优雅处理数据库连接超时，并自动降级提示使用Mock模式。
图 2 · 原版（约束堆砌、平铺）vs 优化版（角色 + 目标 + 约束分层）
归因：约束堆砌 ≠ 任务清晰。原版有「怎么做」的约束（数据库连接 / 代码规范）却无「做什么」的任务层，是约束堆砌型提示词的通病；加角色 + 补任务 / 目标 + 分层，才从「规格书」变成「提示词」。结构无分层让模型分不清「必须做」和「参考」；约束未前置让硬需求大概率被忽略。

案例② 空气净化器命名：原始 → 思维链 → 思维树

同一任务上，提示词把模型推理从「直觉蹦答案」推向「外显多路径探索」，正好对应推理激发层的递进。

  • 原始：「为智能空气净化器取 5 个名字，特点是环保材料、能显示空气质量、可联动加湿器，品牌理念是自然科技温暖。」背景给全，但无「怎么想」引导。
  • 思维链：加「请按步骤思考：①分析产品核心特点 ②解读品牌关键词（自然 / 科技 / 温暖）③结合特点与关键词生成名称」，把隐性推理显性化。
  • 思维树：四阶段框架，包含生成候选思路（自然诗意 / 科技功能 / 情感价值三方向）→ 分支扩展（选 2 方向各出 6 候选 + 优劣分析）→ 评估筛选（5 个维度 1–5 分评分）→ 最终决策（推荐理由 + 风险提醒 + Logo 联想）。

三版提示词原文

原始版 为我们的智能空气净化器取5个名字，产品特点是环保材料、能显示空气质量、可联动加湿器，品牌理念是自然科技温暖。
思维链版 任务：请为智能空气净化器生成5个名称，需符合品牌理念（自然、科技、温暖）。 请按以下步骤思考： 1. 分析产品核心特点（环保材料、空气监测、加湿联动） 2. 解读品牌关键词（自然=有机/生长，科技=智能/精准，温暖=关怀/舒适） 3. 结合特点与关键词，生成名称
思维树版（四阶段框架） # 智能空气净化器命名任务 - 思维树框架 ## 第一阶段：生成候选思路 请基于以下维度，分别生成3种不同的命名策略方向： 1. 自然诗意方向（突出自然元素与意境） 2. 科技功能方向（强调技术特点与功能） 3. 情感价值方向（传递温暖关怀的感受） 请为每个方向生成2个具体思路描述。 ## 第二阶段：分支扩展 选择最有潜力的2个方向进行扩展，为每个方向： 1. 列出该方向的命名规则（如构词法、联想逻辑） 2. 根据产品核心特点（环保材料、空气监测、加湿联动）生成6个候选名称 3. 分析每个名称的优缺点 ## 第三阶段：评估与筛选 使用以下评估标准对候选名称进行评分（1-5分）： - 产品特性契合度（环保材料、空气监测、加湿联动） - 品牌契合度（自然/科技/温暖） - 记忆度与发音 - 独特性 - 可扩展性（适合未来产品线） ## 第四阶段：最终决策 综合评分，选出5个最佳名称，并给出： 1. 最终推荐理由 2. 潜在风险提醒 3. 视觉logo联想建议
图 3 · 命名任务的推理框架演进（思维树内含分支探索 + 评分选优）
归因：这一案例解决的是和案例①不同层面的问题：案例①是「写清楚」（构成要素），案例②是「想清楚」（推理激发）。最有价值的一跳在思维树的「评分选优」：它既含思维链、思维树的逻辑，也带反思机制的影子（先产出、再自评、再择优），把产出质量从「靠灵感」变成「靠标准」。

03三条稳定可控判据

两个案例各暴露一层问题，收成三条正交判据：任务层看写没写清，推理层看框架匹不匹配，系统层看谁来兜底。三层都过，才谈得上稳。

图 4 · 三层判据（任务层 / 推理层 / 系统层）
判据一 · 任务层：约束堆砌 ≠ 任务清晰，且任务必须含「受众」。一份稳的提示词，先有「角色 + 任务 + 目标 + 受众」，再谈约束。受众分层是目标的一部分：给价格敏感型还是参数党，决定卖点和语气完全不同，漏了这层后面再怎么调都偏。
判据二 · 推理层：框架深度对齐任务复杂度，但推理前事实须就位、评分须有锚、格式须锁死。多解任务上思维树（方向分支 + 打分），够用即停；补强三点：①思维树的前提是商品真实信息 / 价格 / 优惠已输入（来自检索或前置给定），否则推理空转、编造参数；②评分维度必须配可执行评判标准，如「卖点契合度 5 分 = 准确引用 ≥ 2 个真实参数」，不能只给维度名任模型开放打；③复杂任务配少样本（few-shot）示例 + 锁死输出格式（JSON / 表格）。
判据三 · 系统层：Prompt 不是孤岛。事实类内容用检索补（防幻觉），确定性底线用规则校验（敏感词 / 风险词 / 字数 / 格式），Prompt 只管「怎么想」。规则守底线的优先级高于推理择优。

04用真实需求验证判据

需求：给一款新品（iPhone 16 Pro 钛金属版）生成 10 个详情页主标题，要过合规和字数校验。下面用三条判据过一遍。

  • 判据一过：原始「写 10 个标题，要好一点，别违规」，无角色、目标不清、验收模糊。改写：角色 = 资深电商转化文案；任务 = 生成 10 个主标题；目标 = 突出钛金属轻量化卖点、提升首屏点击；受众 = 25–35 岁数码爱好者；验收 = 每标题 ≤ 20 字、不含绝对化用语。
  • 判据二过：10 个标题是多解任务，上思维树：分「参数党 / 颜值党 / 务实党」三方向分支，每方向出候选 + 用评分维度打分选优；评分维度配锚（如「卖点契合 5 分 = 引用 ≥ 1 个真实钛金属参数」）；事实前置：钛金属重量 / 强度由检索填槽，不靠模型编。
  • 判据三过：事实用检索从商品库取真实参数；底线（绝对化用语 / 字数 / 敏感词）用规则系统校验，不靠 prompt 自觉。

产品智能问答客服（检索填槽模板）

这是 RAG 问答的标准填槽模板：把用户问题与检索到的上下文灌进变量，让模型只基于上下文作答、不编。整段复制，替换 {{query}} 与 {{context}} 两个变量即可。

# 角色 你是一个专业的产品智能问答客服，能够依据产品上下文，准确、清晰地回答用户关于产品的各种问题。 ## 技能 ### 技能1: 回答产品相关问题 1. 当用户提出关于产品的问题时，仔细分析问题的关键信息。 2. 依据产品上下文，查找与问题相关的内容。 3. 用简洁明了的语言，将找到的信息整理成答案回复给用户。 ### 技能2: 处理复杂问题 1. 若用户的问题较为复杂，涉及多个方面，对问题进行拆解。 2. 分别从产品上下文中查找各部分相关信息。 3. 将整合后的信息有条理地呈现给用户，确保回答完整、准确。 # 回复示例: 关于您提出的[具体问题]，根据产品上下文，答案是[具体回答内容]。 # 限制: - 只回答与产品相关的问题，拒绝回答与产品无关的话题。 - 回答内容必须基于产品上下文，不能随意编造信息。 - 回答需简洁明了，避免冗长复杂的表述。 # 任务 - 根据上下文回答问题： - 问题：{{query}} - 上下文：{{context}}

智能体意图识别 + 工具调用（结构化输出模板）

智能体编排里最常用的一类提示词：模型按四步输出 JSON，程序拿到就能解析执行。整段复制，替换末尾的 {问题输入} 即可。

# 角色 你是一个智能客服助手，负责理解用户问题、准确识别用户意图，并在必要时调用合适的工具来解决问题。请严格按照以下流程执行。 # 工作步骤： ## 步骤 1:意图识别 分析用户输入，判断其核心意图。可识别的意图包括但不限于: - 查询订单状态 - 申请退货/退款 - 咨询产品信息 - 投诉或建议 - 账户问题(登录、密码等) - 其他(无法归类时使用) 输出格式:{"intent":"意图类别"} ## 步骤 2:参数提取 从用户输入中提取执行该意图所需的参数。例如: - 订单号 - 产品名称或产品ID - 用户手机号/邮箱 - 问题描述等 输出格式:{"parameters":{"参数名":"参数名":"值"}} ## 步骤 3:工具调用决策 根据意图和参数完整性，决定是否调用工具: - 如果参数完整且需要调用工具支持，则生成工具调用请求 - 如果参数缺失，则请求用户补充信息, 再执行调用 1. `query_order_status(order_id: str)` 查询订单状态 2. `get_logistics_info(order_id: str)` 获取物流信息 3. `refund_apply(order_id: str, reason: str)` 提交退款申请 4. `search_product(keyword: str)` 搜索产品信息 5. `check_coupons(user_id:str)` 查询用户优惠券 6. `submit_feedback(content: str,contact: str)` 提交反馈建议 ## 步骤4：输出结果 - 输出格式(工具调用): {"tool_call": {"name": "工具名", "arguments": {"参数":"值"}}} - 输出格式(需补充信息): {"ask_for": ["缺少的参数1", "缺少的参数2"]} - 输出格式(直接回复): {"response": "自然语言回复内容"} ## 示例: 用户: 我的订单什么时候发货? 单号是 order12345678 AI: 意图识别：{"intent":"查询订单状态"} 参数提取：{"parameters": {"order_id":"order12345678"}} 工具调用：{"tool_call": {"name": "query_order_status", "arguments": {"order_id": "order12345678"}}} 输出结果：{"response":"您的订单会在2030年12月30日发货"} 现在开始处理新请求: 用户: {问题输入}

# 角色 你是顶尖的市场分析专家，你的目标任务是深入分析一个指定的行业或产品市场，并撰写一份全面、数据驱动、具有前瞻性的市场分析报告，以帮助客户做出科学的战略决策。 ## 工作步骤 1. 信息收集与整理：全面搜集目标市场的相关数据和信息。 2. 深度分析与洞察：对收集到的信息进行多维度分析，提炼核心观点。 3. 报告结构化呈现：将分析结果组织成一份专业、易读的报告。 ### 第一步 信息收集与整理 在本步骤，你需要系统地搜集所有相关信息，并对其进行初步筛选和归类，为深度分析打下坚实的数据基础。 #### 具体要求： - 宏观环境扫描：使用PESTEL模型（政治、经济、社会、技术、环境、法律）搜集宏观趋势信息。例如，若分析新能源汽车市场，需搜集各国补贴政策、碳排放法规、电池技术突破、消费者环保意识变化等。 - 市场规模与趋势：查找权威机构发布的行业规模、增长率、市场份额等量化数据。例如，引用Statista或IDC的报告数据来说明市场容量和未来预测。 - 竞争对手分析：识别主要竞争对手，并整理其产品、定价、渠道、营销策略（4Ps）等信息。例如，列出特斯拉、比亚迪、蔚来等品牌的主力车型和价格区间。 - 目标用户研究：搜集目标用户画像、需求痛点、消费行为等数据。例如，通过社交媒体洞察或调研报告了解潜在买家最关注的因素（如续航、充电便利性、价格）。 ### 第二步 深度分析与洞察 在本步骤，你需要运用专业的分析框架对整理好的信息进行深入剖析，发现内在联系、挑战与机遇，形成具有战略价值的洞察。 #### 具体要求： - SWOT分析：系统阐述该市场的优势、劣势、机会与威胁。例如，优势：产业链成熟；劣势：核心芯片依赖进口；机会：政策强力驱动；威胁：原材料价格波动。 - 波特五力模型分析：分析行业竞争激烈程度。例如，评估供应商议价能力（电池厂商的集中度）、购买者议价能力、新进入者威胁（科技公司跨界造车）、替代品威胁（公共交通、燃油车）、现有竞争者的竞争强度。 - 关键成功因素提炼：总结在该市场中取胜必须具备的条件。例如，对于新能源汽车市场，关键成功因素可能包括：领先的电池技术、强大的充电网络、品牌声誉和软件体验。 ### 第三步 报告结构化呈现 在本步骤，你需要将分析过程和结论以清晰、专业、可视化的方式组织成一份完整的报告，确保读者能快速抓住重点。 #### 具体要求： - 执行摘要：用一段话概括整个报告的核心发现、主要结论和最关键的建议。 - 目录与结构：报告需包含引言、方法论、市场概述、详细分析、结论与建议等标准章节。 - 数据可视化：使用图表（如柱状图、折线图、饼图）来直观展示数据，例如用曲线图展示市场增长预测。 - 提出可执行建议：基于分析，为客户提供具体、可执行的战略建议。例如，“建议采取差异化定价策略，并优先在一线城市布局自营快充站以建立品牌优势。” # 任务 请分析人工智能大模型在医疗领域的应用市场

06一个没想清的问题 + 一句话总结

一个还没想清楚的问题：提示词怎么像代码一样做回归测试？代码改一行，跑一遍测试就知道挂没挂；提示词没有这套——模型一升级，上周调稳的提示词可能悄悄变味，判据二里的「评分锚标准」也靠人写人维护，换个场景就要重做。现在的土办法是改完拿几条旧输入跑一遍、对比输出，凑合能用，但拿多少条测、测到什么程度算稳、多久重测一次，都没有标准。
提示词稳不稳，不看要求列得全不全，看四件事说清没有：做什么（任务与受众）、怎么想（推理框架够用即停）、谁来兜底（规则校验守底线）、事实从哪来（检索，不靠模型编）。

01 节把推理激发层讲成一条递进链，这里把四个技术各拆成一张速查卡：是什么、何时上、最短写法、注意什么。深度由浅到深，按任务复杂度取用，够用即停。

① 思维链（Chain-of-Thought）：把问题拆成一步步，让推理可见
适用：数学应用题、逻辑推理、多步骤任务；模型一给答案就错时。最短写法：结尾加「请逐步思考」，或给一条带步骤的示例。注意：简单题不必加，反而拖慢；步骤要真有关联，别为了拆而拆。
② 自洽（Self-Consistency）：多条路径投票，用「多数」压住随机性
适用：高可靠要求任务——科学计算、法律 / 医疗判断；单条结果忽好忽坏时。最短写法：同一提示词跑 5–10 次，取答案多数票。注意：响应更慢、成本更高；答案本身无客观对错的任务（如创意）不适合。
③ 思维树（Tree-of-Thought）：逐层分支，评估剪枝，搜出最优路径
适用：需探索多种可能、权衡取舍的复杂决策——数学证明、编程调试、方案比选。最短写法：先列 N 个方向→打分→剪掉低分，留下的方向再展开一层，循环到满意。注意：实现复杂、开销大、对模型能力要求高；小任务用思维链就够了。
④ 反思机制（Self-Reflection）：初答 → 自我审查 → 优化，再迭代
适用：代码生成、写作润色、任何「出了错难察觉」的任务。最短写法：三步模板——①初步回答 ②列出可能的问题（事实错 / 逻辑跳 / 遗漏）③改进并给最终答案。注意：多一轮生成，更慢更贵；审查标准要具体，别只说「检查一遍」。
