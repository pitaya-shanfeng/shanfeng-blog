## 一、BRD、MRD的解析

### 1、名词概念

#### （1）BRD的概念

BRD全称是“Business Requirement Document”，翻译为中文即是商业需求文档，大多数的商业行为是以高于成本的价格卖出商品或服务来盈利的，商业需求文档应该以商业为核心，以产品为内容，以对象为公司高层，为说明产品的商业模式、产品规划、产品框架、风险控制而编写的文档，简而言之：商业需求文档指的就是基于商业目标或价值所描述的产品需求内容文档。

#### （2）MRD的概念

MRD的全称是“Market Requirement Document”，翻译为中文便是市场需求文档，MRD是产品经理在与企业高层明确了某件事情或者说某个产品值得一做后，描述这件事情应该怎么去做，并且说明这么做的原因，是BRD文档进一步的细化和理论支撑。

### 2、文档形式

#### （1）Word文档

既然称作BRD文档、MRD文档，大家能想到的第一个形式自然是便是word形式的规整文档，根据应该所覆盖的层面及内容结构去梳理相关资料及分析，通过整理简易的目录形式展现具体的一份文档。这样的一份文档资料齐全覆盖面广泛，且适合所有人员日后查看；但是两份文档核心内容为用于在产品投入研发之前，由相关人员用来评估的重要依据，那么对于这些面向的人群尤其是BRD文档面对的一些高层人员，一般情况下大家的时间是宝贵的，且手头上通常除了掌握大量资源的同时还肩负着公司多项工作，他们是很难有空去仔细的看这样一份文档，所以一份word文档既有其好处也有其一定的缺陷。

#### （2）PPT文档

产品经理任职要求通常都有这样一条，即要求产品岗位人员善于与各部门人员沟通，所以可想而知，如果你是一位产品经理或者说产品相关人员，你去与大家沟通的时候，主要是靠语言还是文字？ppt文档通常应用场合都是配合着演讲进行的，企业高层、相关涉及人员和你都希望能在最短的时间内了解他们最迫切想要知道的事情，一份word文档理解起来并不如一份演讲+图文的ppt理解的快。但是这时候问题就来了：ppt这么方便那为什么还有那么多人要去写word形式的文档呢？因为ppt文档的使用是有一定前提的，首先你要善于演讲，其次相关面向的人员能有精力聚在一起听你演示，除此之外ppt文档主要是靠演讲者进行描述，所以没法再日后进行全面的回忆与记录，故一份ppt文档既有其好处也有其一定的缺陷。

### 3、背景目的

#### （1）BRD的目的

为什么要去写BRD文档，我们写BRD文档的目的在于什么？相信这个问题才是大家在写BRD文档前需要考虑清楚的事情。通常一家互联网企业中拥有不止一个项目，可能只有一个产品但是项目却不止一个，也可能产品也有多个。通常一个产品经理或者产品团队发现了现有产品拥有改进的可能或者说发现一个新产品的创新可能，这时候产品经理需要与高层进行沟通，希望公司能够给予相关重视，说白了其实就是产品经理需要三件东西：权重、项目、资源，更明白的说就是：人力资源、开发与运营成本、项目关注度、领导支持等（就是人和钱）。

#### （2）MRD的目的

通过BRD明确这件事值得做之后，描述应该怎么做，并说明这么做的原因。如果说BRD是抛出了论题，那么MRD就是要我们用论点来支撑BRD，同时通过论证来得出我们采用什么样的方式获得BRD的商业目标。就是经过一系列分析后，拿出一套我们认为最适合干这个事情的方法以及指导实施的文档。

### 4、面向对象

#### （1）BRD的面向对象

| 对象       | 描述                                                         |
| ---------- | ------------------------------------------------------------ |
| 资本管理层 | 首席财务官、财务总监等，他们能够为我们提供充足的产品研发和推广经费，钱是他们最关心的，希望得到他们的经济支持，文档的侧重点就应该在产品的支出和盈利，还要体现出产品的市场潜力和发展势头，他们关注的有：投入产出比、收益预测、营收增长率等。 |
| 市场管理层 | 市场总监、运营总监，他们能为我们提供完善的运营资源。他们关注的有：外部环境、推广渠道、竞争对手、市场空间、营销资源等。 |
| 研发管理层 | 技术总监、技术主管等，他们能为我们提供充足的技术资源，他们最关心的是技术强度、工作量、研发成本等，因此向技术人员汇报时应该侧重于产品定位、产品规划、产品框架、产品方向、工程进度和人力需求。 |
| 战略管理层 | 老板、董事长、首席执行官、运营总监等，他们能决定我们的产品的权重资源，他们比较关注我们要做的产品是否是潜在市场或新兴市场，是否有长期投资的价值，未来的趋势如何，风险是否可控，是否合拍公司的战略规划等。 |

## 二、BRD的内容结构

### 1、方案背景

在说明产品的改进的可能性或者阐述一个新产品的之前，我们需要先描述整个方案背景。描述背景的所有的数据最好注明数据来源，可以通过上市公司财报、艾瑞咨询或一些知名网站的采访文章来获取数据，甚至是内部人士的消息，这些都是重要的参考来源。

#### （1）市场分析

不能闭门造车，还要看看市场上的情况，这个市场分析包括以下几个方面：

| 考虑方面 | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 市场规模 | 这个数据需要通过对需求的分析，对人群判断后评估得出，决策者会通过这个判断值不值得投入 |
| 市场趋势 | 未来市场竞争格局，行业的风险，政策的变化, 行业的发展方向等判断 |
| 市场机会 | 我们在市场上的机会在什么地方，怎么找到突破口，这个机会可以让我们发展成为一个什么样的地位 |

#### （2）竞争分析

通过波特五力分析模型得出当前行业竞争对手的发展情况，以及对自身产品进入该市场所可能面对的竞争压力，从而为自己的产品杀出市场提供参考和可行性对比。

#### （3）用户分析

针对产品和对应的市场进行用户分析，主要通过数据的分析得出该市场的用户具有什么特征，有什么需求痛点，用户的这些问题是否迫切、强烈以及出现频率是否足够高，如有需要，可以描绘三至五个用户画像，直观的构建产品/该市场的用户特征。

![](/assets/library/notes/brd-mrd/doc2/image-20210225224613693.webp)

### 2、产品规划

产品规划主要是包括对于产品的定位、产品的核心目标、产品的结构和迭代路线进行一个整体的呈现。这部分内容主要是基于当前产品的规划，描述以下内容：

| 内容     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 产品定位 | 一句话描述想要做一件什么样的产品                             |
| 核心目标 | 做这个产品想要实现的目标，从产品的定位为基准，可以包括经济收益、用户增长、影响力、市场占有率以及对于公司战略的重要性等 |
| 产品结构 | 描述产品矩阵及产品形态，无需精确到细节；以xmind等思维导图软件，将产品结构直接画出来 |
| 产品路线 | 描述各个阶段达成的目标，把产品的迭代路线写出来，把各个阶段的功能、特点、目标进行梳理，要求精练，讲重点 |

![](/assets/library/notes/brd-mrd/doc2/image-20210225224752376.webp)

### 3、运营规划

完整的运营规划，包括内容运营，用户运营，社区运营，活动运营，产品运营五个方面，但是并不是所有的产品都会占据所有的运营方式，每个产品的运营涉及的部分不一定一样，侧重点也不一样。

| 内容     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 内容运营 | 主要是分析产品中的内容的生产与传播：内容谁来生产？内容生产的策略有哪些？以什么方式呈现给用户？ |
| 用户运营 | 主要是拉新，维持活跃，提升留存，唤醒沉睡用户：包括拉新的方式选择什么？通过什么样的方式刺激用户注册？有什么方式提高用户的活跃？ |
| 社区运营 | 不是每个产品都需要做的，需要考虑社区要如何活跃：社区讨论是否有限制？社区的内容由谁来做？谁来管？ |
| 活动运营 | 主要涉及的各类活动策划，活动执行，活动复盘，活动转化：活动如何执行？谁来执行？怎么执行？如何推广？ |
| 产品运营 | 主要是通过运营数据、埋点数据进行的产品规划运营：通过分析产品的各类数据来进行优化。更新改善产品的各项指标的运营活动 |

![](/assets/library/notes/brd-mrd/doc2/image-20210225224942449.webp)

### 4、盈利模式

盈利模式就是这个产品通过什么方式来赚钱，区分产品业务模块并结合各模块的特点来分析现阶段的盈利模式、将来可能的盈利模式。盈利模式包括广告变现，增值服务变现，电商变现等。

![](/assets/library/notes/brd-mrd/doc2/image-20210225225022955.webp)

### 5、收益与成本

#### （1）收益预估

收益并不只是代表产品带来的经济收益。产品带来的收益包括经济收益，也包括用户增长、影响力、市场占有率、以及对整个公司战略层带来的收益。由于产品定位和公司的目标不同，每个产品所需要达到的收益可能也不尽相同。总地来说，收益结构主要是包括了以下方面：

| 内容       | 描述                                                         |
| ---------- | ------------------------------------------------------------ |
| 经济收益   | 按照盈利模式，从不同的方式进行分析，将产品会带来的经济收益进行一个较为细节的汇总和预算。 |
| 用户规模   | 在于分析产品目标体系内用户数量级的提升                       |
| 品牌影响力 | 不同地区、线上和线下用户的认知度，品牌渗透的不同地区，不同人群，获取品牌溢价效应 |
| 市场份额   | 结合目前的市场情况，根据产品的目标和现状综合来说明产品市场份额的预期占有率 |
| 战略规划   | 从公司的战略规划入手，描述产品能够给公司带来的战略层的影响   |

### 6、风险与对策

根据产品、业务的特征和所在的行业、市场，在真实投入市场后，获取用户、收益的同时也必然要面对一系列的挑战，这些挑战可能来自于外部、也有可能来自于内部，为了避免届时造成过大的影响，需要在起初就要思考风险及相应对策，从而实现业务的良好闭环及风险预估、对冲等。

| 风险类型 | 描述                                             |
| :------- | :----------------------------------------------- |
| 政策风险 | 政策管控、监测、干预等                           |
| 技术风险 | 核心技术泄露、技术实现不了、黑客、盗版等         |
| 法律风险 | 盗版、侵权、涉黄涉赌等，制假售假、商铺审核不严等 |
| 市场风险 | 竞品的威胁、上下游的威胁等                       |
| 决策风险 | 战略决策失误、部门决策失误等                     |
| 资本风险 | 资本退出、资本引入缓慢等                         |

相关对策：

- 能规避的规避——如技术风险，招聘技术顶尖人才，或找外援、加强核心员工管理，做好保密措施。
- 能转移的转移——如决策风险，产品相关人都参与决策，分担决策风险。
- 能缓解的缓解——如市场风险、资金危险缓解的最好方法就是自己拥有强大的造血功能，即稳定的盈利能力和现金流。
- 能接受的接受——如政策、法律风险，必须接受

## 三、MRD的内容结构

### 1、文档说明

文档说明在很多人看来基本是不太在意的部分，但是这却是不可缺少的一部分，产品由无至有的过程中，存在很多不稳定因数，就像未来的PRD文档或产品一样，会修改多次甚至诞生多个版本，所以在一开始就养成文档说明是非常有必要的，方便未来参与到产品路线的其他同事都能更清晰的了解整个产品。虽然产品经理是一群有理想有创新的一批人，但是并不意味着天马行空，所以该按流程与规范的东西还是好好遵守吧。

![](/assets/library/notes/brd-mrd/doc2/image-20210226101050653.webp)

### 2、市场说明

描述一下你们要做的是什么市场，包含市场规模、市场特征、发展趋势、市场问题、市场机会等信息，市场分析中的数据并不是虚构的，也是不容产品经理去随意臆想的，通过相应的市场调差手段，提供相应的数据资料是最好的选择。

| 内容     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 目标市场 | 主要从市场规模、市场特征、发展趋势、市场壁垒等方面进行分析   |
| 市场问题 | 列举市场痛点，用户在需求产生后，遇到的各个环节的问题，目前市场是如何满足的，以及那些需求点尚未得到满足或满足不够有深度挖掘的空间 |
| 市场机会 | 根据市场的问题，分析问题，是否还有机会做这个市场？根据市场凸显的问题，举例出几种解决方案，逐一举例。 |
| 分析结论 | 对整个市场分析模块，进行提炼与总结                           |

![](/assets/library/notes/brd-mrd/doc2/image-20210226101320026.webp)

### 3、用户说明

| 内容             | 描述                                                         |
| ---------------- | ------------------------------------------------------------ |
| 目标用户群体     | 将目标市场中的用户进行有规律的划分，通常对用户基本基于年龄、收入、性别、学历、地区等几个方面来划分 |
| 目标用户特征     | 在这个阶段，主要工作就是对目标群体进行一个总结归纳，找出他们的共性特点与非共性特点 |
| 建立虚拟用户角色 | 用户角色卡片，根据用户角色卡片针对目标用户群体进行归类划分，抽取典型样本 |
| 用户使用场景     | 将产品放进用户角色中，讲故事，可以发动所有人去做这件事情     |
| 用户动机         | 这里不要刻意去将产品因素带入进去，实话实说，要求最真实的表象 |
| 用户目标         | 这就是常说的挖掘用户说不出来的真实目的，就比如人们想要更快的交通工具，福特给了他们车一样的感觉，大家自己体会 |

### 4、竞品说明

#### （1）确定竞品

竞品主要分为两类，一类是直接竞品，一类是间接竞品。

| 内容     | 描述                                                         |
| -------- | ------------------------------------------------------------ |
| 直接竞品 | 产品定位、商业模式一致的竞品。产品框架、交互、功能有直接的参考价值。重点列举各直接竞品的产品形态、背景、目标用户、商业模式及上线后的产品迭代，用户规模，甚至融资情况等 |
| 间接竞品 | 重点描述间接竞品的产品定位，在市场下的细分市场，以及描述产品主线（或业务） |

#### （2）竞品的模式分析

竞品的商业模式、竞品目标用户、竞品运营推广策略、竞品技术分析、竞品市场份额。从这几维度展开分析。

| 内容         | 描述                                                         |
| ------------ | ------------------------------------------------------------ |
| 商业模式     | 对比产品在定位、服务、功能、盈利模式的差异。是对直接竞品内容的详细展开。 |
| 目标用户     | 各个竞品依据产品定位的差异，或者产品推广方式、覆盖地区的不同目标用户的构成也会不同 |
| 运营推广策略 | 从运营、推广、营销策略等角度剖析产品的迭代历史               |
| 技术分析     | 包括技术壁垒，项目研发可能碰到的技术壁垒。如人工智能、语音图像识别等。如果觉得这是一大优势的话，可以详细展开。 |
| 市场份额     | 从不同维度，阐述竞品间的市场情况。快速了解竞品在市场的情况。如：各大应用市场的安装量、活跃用户、地区分布、用户增长率等。 |

### 5、产品说明

| 内容             | 解释                                                         |
| ---------------- | ------------------------------------------------------------ |
| 产品定位         | 产品有越做越复杂的可能性，但是在一定的时间内，定位决定了产品的一切。产品定位一定要做到一句话就可以描述清晰 |
| 产品核心目标     | 主要描述你的产品解决了用户啥需求或产品本身应该要达到一个什么样的目标 |
| 产品结构         | 主要描述产品的主要流程与结构，这里通常指的不是功能结构，而是产品自身的一个整体结构。 |
| 产品路线图       | 要对产品要走的路线及未来发展做出计划，可以由任务节点作为导向进行规划 |
| 产品功能性需求   | 例如：用户的注册登录功能、充值功能、提现功能、购买功能、留言功能、修改密码功能等 |
| 产品非功能性需求 | 非功能性需求主要描述系统特性，主要包含：有效性、性能、扩展性、安全性、健壮性、兼容性、可用性、运营需求等 |
