3.1 私域管理系统处置方案

现状：私域管理系统未与大平台任何系统打通，只有群发能力，无用户视图/标签/营销画布。已明确不迭代，计划逐步废弃，由有机云替代。

私域管理系统处置路径：过渡→部分替换→迁移→下线（不等营销画布，有机云打通后即可独立替换部分能力）

关键调整：私域系统处置不等阶段三。阶段二有机云单向打通后，加粉、群发/私发、好友管理即可被有机云独立替换——这些能力不依赖营销画布。营销画布上线后（阶段三），群管理、活码、标签等剩余能力继续迁移，私域系统逐步停用。
迁移数据清单：好友关系→有机云 · 用户标签→标签体系 · 群管理→有机云 · 群发/私发→营销中心+有机云 · 活码/话术→有机云 · 素材库→营销中心CMS · 加微名单→营销中心营销画布 · 统计数据→数据看板（人工梳理后导入，不自动同步）

3.2 有机云接入方案

现状：有机云是计划对接的SCRM系统，已具备完整的企微SCRM执行能力（加粉、群发、群管理、活码、话术、人群包、聚合客服等）。AI外呼已作废。

定位：有机云是企微渠道的执行端。所有编排型动作（加粉、SOP群发、群管理、人群触达）由营销中心编排，通过API推送用户名单和任务给有机云自动执行——不是业务同学在有机云后台手动操作。有机云自身保留的工具能力（活码、话术、聚合客服、素材库等）属于被动响应型，无需任务驱动。

3.3 用户中心建设方案

核心问题：①用户身份未统一——租赁、赊销各自独立userid，一个用户既是租赁用户又是赊销用户时系统认为是两个人，APP/小程序无法同时承载两个业务；②无可视化后台——业务连查用户都不能做，运营无法自助看数据。已沉淀登录、二要素、人脸、OCR、联系人等基础数据。

OneID（用户中心的子模块）：通过手机号+设备指纹+业务线标识，将各业务线userid映射到一个统一用户ID上。解决"一个人被识别为多人"的问题，是用户中心最底层的能力，阶段一上线即开放ID查询服务，阶段三稳定运行后开放ID写入。

用户中心四阶段演进路径（含OneID子模块），与系统演进路线图对齐

边界：用户中心只管"用户是谁"（OneID唯一身份 + 基础信息+档案）和"用户怎样"（展示标签体系产出的标签）。打标和圈选的计算逻辑不在用户中心，由标签体系独立承担。

现状：老标签工厂已废弃，神策未打通。空白。方向：独立板块，全量打标能力（用户/商品/订单/商户）+ 人群/商品圈选匹配。

标签体系四层架构：数据来源→原子标签→非原子标签→圈选匹配

3.5 营销中心建设方案

现状：已有短信、订阅消息2条通道 + CMS/RMS内容搭建 + 优惠券 + 搜索榜单 + 千人千面接口（需外部输入人群）。核心缺口：各通道目前独立建任务、各自驱动，缺少一个统一的编排板块来衔接——即"营销画布"。

营销画布是什么：一个可视化的用户运营编排工具。运营在画布上配置：针对某类用户 → 在什么节点 → 用什么方式触达 → 触达后等待/判断 → 执行下一个任务节点。把短信、订阅消息、企微/有机云、APP push等通道串联起来，实现自动化、多节点、多通道的协同触达。

画布节点类型：事件触发（设备归还→召回券）· 时间触发（到期前30天→续租推荐）· 状态触发（还款50%→进度通知）· 动作节点（发短信/推订阅/下发有机云/发券）· 判断节点（是否已读/下单→分支）· 等待节点（等待N天→下一节点）

营销中心四层架构：规则配置→执行→数据回流→已有能力复用

能力现状阶段一阶段二阶段三阶段四
触达通道短信+订阅（各自独立建任务）有机云对接方案+企微/有机云单向打通+双向闭环+营销画布+APP push
营销画布无画布规则定义（文档）—上线（事件/时间/状态+多节点编排）升级（AB+频次+归因）

数据回流不明有机云对接字段清单—触达记录+转化追踪效果归因+AB对比
营销画布是核心缺口。没有画布，各通道只能独立人工操作。阶段一先定义画布规则（文档），阶段三建设画布（事件/时间/状态三类触发+多节点编排），阶段四升级（AB测试+频次控制+效果归因）。自研还是外采需在阶段二结束前决策。

运营策略与动作

目标：用现有工具把短租复购SOP人工跑通，验证"到期前触达能否提升复购率"。
策略：运营端短租先行→人工SOP验证→数据驱动升级；产品端需求定稿→技术排期→地基动工。两端并行。
