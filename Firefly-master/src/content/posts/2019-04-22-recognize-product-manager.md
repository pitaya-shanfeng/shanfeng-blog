## 一、变迁与发展

### 1.1 历史演变

在互联网行业内，产品经理一直以来都是一个举足轻重的角色，可能很多人都会认为产品经理是一个新兴岗位，甚至还在纠结这个岗位没有一些输出代码的开发工程师岗位更有底蕴，实际上产品经理很早就已经诞生。

#### **1、消费品时代**

产品经理这个名词，最早是在1932年，由宝洁公司的麦克埃尔洛埃提出的，当时他认为：为了提高效率，应该由一个人来统一管理、负责一条产品线或一个品牌的整体规划、运作，并率先在宝洁内部开始了尝试，于是他成为了历史上首位产品经理。当时产品经理的主要职责是做定位、做营销、做渠道。 

#### **2、软件时代**

互联网诞生之初，涌现了许多面向企业的软件公司，产品经理通常和销售人员一起沟通客户，了解客户明确的需求，并将之转化为功能，推动开发并上线客户需要的功能。产品经理通常只需要保证产品不会经常出漏洞，完成更多客户需求是投入产出比最高的方式。随着行业的发展，形成了一些较大的软件公司，由此产品经理划分为三类岗位：

- 第一类是产品市场经理，也就是面向市场的产品经理，主要研究用户的需求。受制于当时的技术条件，主要通过用户调研、访谈和小数据量级的分析做用户需求研究，效率较低。
- 第二类是产品经理，负责产品功能的解决方案设计，满足从产品市场经理处接收到的用户需求。
- 第三类是项目经理，主要负责各种项目的管理，通过团体管理和协调，确保项目交付 。

#### **3、移动互联时代**

移动互联网爆发，重新定义了产品经理，人员大量涌入这个领域，这个岗位也慢慢开始为中国互联网行业所熟知和认可，并由于其稀缺性和一定程度上的神秘性，一度成为了互联网业内最火爆、最引人瞩目的岗位。

### 1.2 重新定义

>

>

>
> 3、产品推广：有针对性地开展产品推广，增加用户积极性和参与度，并配合产品需要进行推广方案策划。

> 3、具备较好的业务理解能力和业务模型抽象能力，产品分析和架构设计能力，理解并运用业务和产品的衡量指标。 
>
> 4、善于跨团队合作协调，逻辑化思维，清晰表达，具备一定的项目管理技能，认同互联网和电商的前景，富有创业激情。

#### **3、概念定义**

产品经理（Product Manager）也称产品企划，是指在公司中针对某一项或是某一类的产品进行规划和管理的人员，主要负责产品的研发、制造、营销、渠道等工作。产品经理需要考虑目标用户特征、竞争产品、产品是否符合公司的业务模式等等诸多因素。一般而言，产品经理管理的是一个或者多个有形产品。但是，产品经理也可以用于描述管理无形产品如音乐、信息和服务的人。产品经理是很难定义的一个角色，如果非要一句话定义，那么产品经理是在产品整个生命周期内，为终端用户服务，从而实现用户价值与商业价值的人。

### 1.4 岗位分类

产品经理分为哪几种？打开各大招聘网站搜索产品经理，会出现各种各样的产品经理，职责和能力要求也存在各种差异，产品经理之所以难以分类，一方面固然是本身产品经理的工作职能界定中国目前尚未形成一套非常严谨的标准化体系，另一方面也是因为，分类的角度实在太多了，很难抽象化。接下来，我们通过互联网行业常见的产品经理来进行一个简单的总结归纳：

| <span style="display:inline-block;width:150px">分类</span>             | 描述                                                         |
| :--------------- | :----------------------------------------------------------- |
| 用户产品经理     | 主要直接面对用户、实现业务                                   |
| 策略产品经理     | 主要负责研究和制定公司公司的业务策略、战略布局、调整产品策略和业务发方向 |
| 商业产品经理     | 围绕最大化程度实现产品的盈利点，挖掘商业潜能，最大化实现产品价值、为企业实现更大利润 |
| 数据产品经理     | 主要负责从数据纬度出发分析业务，搭建业务框架，用数据的手段提升整体业务水平，为其他团队提供数据支撑 |
| AI产品经理       | 负责AI相关项目产品的规划、设计                               |
| 企业服务产品经理 | 负责企业内部或提供企业三方服务产品的规划、设计               |
| CRM产品经理      | 负责CRM系统搭建、规划、设计                                  |
| OMS产品经理      | 负责OMS系统搭建、规划、设计                                  |
| WMS产品经理      | 负责WMS系统搭建、规划、设计                                  |
| FMS产品经理      | 负责FMS系统搭建、规划、设计                                  |
| 供应链产品经理   | 负责跟进公司产品从原材料采购到生产出来的整个链条             |

### 1.5 职业发展

| <span style="display:inline-block;width:150px">阶段</span> | 描述                                                         |
| :--------------------------------------------------------- | :----------------------------------------------------------- |
| 产品助理（或其他）                                         | 由一个门外汉踏入产品相关的岗位，这个阶段做的东西会比较多、比较杂，可能有些工作甚至与产品无关 |
| 初级产品经理                                               | 开始真正的接触从事产品相关的工作，处在学习尝试的阶段，能够设计一些小的功能模块，开始尝试画原型、写文档 |
| 中级产品经理                                               | 能够产出逻辑严丝合缝、用户体验良好、界面优雅美观的产品原型跟文档 |
| 高级（资深）产品经理                                       | 关注的角度由界面细节、产品功能扩展到整个产品、整个战略上；除了产品本身之外，还同时管理协调各部门资源，此时此刻你是对一个团队负责，对产品价值负责。 |
| 产品专家（专业线）                                         | 在产品专业路线上深耕，极其擅长特定领域的产品架构和设计，具备产品业务模型的抽象和搭建，专业技能熟练，项目经验丰富且具备独到的产品视野 |
| 产品总监（商业线）                                         | 在具有较强的产品技术能力之上，还具备产品全生命周期管理的能力，能够带领产品团队从0-1搭建产品，推动产品商业化，并主导产品不断迭代，具备产品战略、规划、落地能力，对人提出更多维度、更高的要求 |

## 二、定位与规划

### 2.1 产品思维

如何去定义产品思维，其实有很多种说法，我个人觉得产品思维其实就是：发现问题并提出解决方案，进而能够将问题的解决方案产品化的一种思维。

| <span style="display:inline-block;width:150px">步骤</span> | <span style="display:inline-block;width:200px">概念</span> | 解释                                                         |
| :--------------------------------------------------------- | :--------------------------------------------------------- | :----------------------------------------------------------- |
| 发现问题                                                   | 问题是什么？                                               | 1、把自己看成消费者，在遇到同样的情况时你会做什么样的选择、有什么样的感受<br />2、通过数据分析发现问题，数据的涨跌和趋势表现，都是业务情况的精确反映。 |
| 分析问题                                                   | 为什么会产生这个问题？                                     | 通过各类需求分析方法，寻根究底、找出问题根本原因             |
| 解决问题                                                   | 如何解决这个问题？                                         | 商业的发展方向，一定是向着更高效率的方向发展。通过提升业务参与某个或多个主体的效率，能大幅提升交易 |
| 产品化                                                     | 产出解决方案并标准化                                       | 通过归纳提炼，总结共性，最终落地为产品、产品功能、服务，进行自动化、规模化解决同一类问题 |

### 2.2 价值观

产品经理做产品，有一些通用性的大原则，能指导更好的做产品，这些大原则就源于产品经理的价值观：

#### **1、善良**

善良是这一种选择，善良比聪明更重要。这里说的善良，是对用户善良，也就是我们说的以用户为中心。以用户为中心是一句被我们说烂，但是在收入、KPI、利益下很难去坚持的话。很多时候，企业会为了其他因素或只看到短期利益而牺牲用户利益；但从长远来看，商业价值是建立在用户价值之上的，只有满足好用户价值，商业价值才能更加有空间。一切商业的起点，都是消费者获益。作为产品经理，我们要坚守善良、坚守用户为中心，当我们都放弃了，就真没有人坚守了。 

#### **2、平衡**

产品是一个综合解决方案，产品最终目是解决用户问题，同时也要把钱赚了。不赚钱的产品是活不长久的，更不用说持续帮用户解决问题了。所以前面说的对用户善良，并不是不考虑商业化，而是在这基础上考虑商业化。用户价值和商业价值是天平的两端，不能漏掉某一端，不能偏向某个极端，需要做好平衡。一个完整的产品，主要有用户、商户和平台三部分，产品经理一开始就要考虑到三者间的平衡，而不是等到想商业变现时，才补充这一环。当然，很多产品前期不赚钱，后面才考虑赚钱。但是什么时候去赚钱是产品发展阶段决定的，而如何去赚钱一开始就要想明白。 

#### **3、简单**

简单的背后是复杂，简单的理念是先做加法再做减法，简单的逻辑是把一切想清楚后用最简单直接的方案去解决本质问题。简单不只是界面设计简单，它的范围包括模式简单、逻辑简单、界面简单、操作路径简单。简而言之，简单，让产品有力量，让产品有竞争力。

### 2.5 工作职责

之前我们对产品经理做了一个定义：**产品经理是在产品整个生命周期内，为终端用户服务，从而实现用户价值与商业价值的人**。那么产品经理具体应该如何做，具体的职责又是什么：

#### **1、战略规划**

产品经理要根据企业的目标，规划产品在不同时间，不同阶段应该如何做才能推动企业战略，达成目标。产品经理需要考虑将产品带入哪个方向，哪个领域，根据这些思路，决定了产品的很多大是大非的问题，比如目标市场是什么，目标用户是什么，盈利模式是什么，甚至产品的气质和风格等。要做好这件事情，产品经理得了解市场，了解竞争对手，有精明的商业头脑。 

#### **2、需求管理**

当产品经理将公司的战略转化为产品的目标后，就需要从中挖掘需求。这些需求不光是来自用户的，还可能是市场需求，公司内部的需求等。产品经理不但需要想可能会有哪些需求能满足产品的目标，还要深刻的分析哪些需求应该做，哪些需求不应该做，这些需求优先级是什么，应该如何做。要做好这些，产品要了解用户，了解市场，能够挖掘数据，能够观察竞品，能够有很强的的逻辑分析能力及自我管理能力等。

####  **3、项目管理**

推动产品就是指产品经理完成了前期的规划和设计，那么需要利用各方资源把这个事情推动下去从而实现，否则就会一直停留在想法上。要做好前面2个不难，顶多是自己的事情，但是要推动产品却要求很强的团队合作管理能力。通常企业里面产品经理大多情况下是没有实权的，用研设计开发都是属于其他部门的公共资源，产品经理不但要去争取这些资源，还要协调他们同心协力的完成目标，这就是产品经理管理者的一面。
